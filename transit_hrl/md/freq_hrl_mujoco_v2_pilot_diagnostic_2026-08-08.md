# Freq-HRL MuJoCo v2 Development Pilot Diagnostic

Date: 2026-08-08

## Audit Boundary

The pilot contains 36 cells: three environments, four methods, and three
independent development optimizer seeds. Each cell has five held-out paths for
the standard task and five paths for each of four deterministic disturbances.
Those five paths are repeated measurements within one trained policy, not five
independent training replicates.

The integrity audit found:

- 36/36 expected cells and 900/900 expected evaluation rows;
- one verified source revision, `76b3d1ba7eacdf2d84c5b95f29d407bf5e9e5aff`;
- complete 65-row training histories and consistent checkpoint selection;
- no protocol or seed-role errors;
- 36 legacy warnings because v2 recorded a model-parameter hash but did not
  independently record the serialized checkpoint file hash.

The machine-readable audit is generated by
`freq_hrl.experiments.mujoco.pilot_analysis`. Its output is development-only
and is excluded from confirmatory claims.

Freq-HRL therefore has a real learning signal and one positive environment,
but v2 does not establish a general control advantage. Frequency routing beats
generic HRL strongly on HalfCheetah, is mixed on Hopper, and is slightly worse
on Walker2d. The leakage-enabled model does not reliably beat its no-leakage
ablation.

## Root-Cause Findings

1. The v2 collection budget is 500 primitive transitions while the upper
   period is 16. Every training path therefore terminates four steps into an
   upper macro action.
2. v2 treated environment truncation and collection boundaries as zero-value
   terminals. This biases both flat and hierarchical GAE, with a distinct
   duration-dependent effect on the upper SMDP critic.
3. The leakage cost subtracted an absolute power budget from causal LF power.
   Seven of nine constrained cells observed no positive cost at all; the two
   active cells saw only tiny maxima. The dual variable consequently remained
   effectively at its initialization.
4. Even on a zero-cost batch, the random cost critic could produce a normalized
   cost advantage and perturb the lower actor whenever the multiplier was
   positive.
5. The v2 field named `frozen_checkpoint_sha256` hashes model parameters, not
   the serialized checkpoint file. The before/after mutation test is useful,
   but the artifact-integrity name and contract were incomplete.

## v4 Repair Gate

Protocol v4 makes the training budget divisible by the upper period, separates
trace boundaries from true MDP terminals, bootstraps reward and cost critics
independently, suppresses constraint actor gradients on zero-violation batches,
uses normalized causal LF RMS budget excess, and records both parameter and
file hashes.

The next experiment order is fixed:

1. run a four-cell v4 preflight on `node001-node006` through scheduleurm;
2. run the 36-cell fresh-seed v4 development pilot;
3. compare v4 learning curves and standard returns against this v2 diagnostic;
4. select a larger transition budget without using formal optimizer or held-out
   seeds;
5. freeze source, hyperparameters, budget, hypotheses, multiplicity families,
   and final seeds before confirmatory execution.

No v2 result may be described as confirmatory MuJoCo evidence.
